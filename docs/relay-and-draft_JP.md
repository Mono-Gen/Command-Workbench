# 中継役での通信の記録と、定義の下書き

[English](relay-and-draft.md)

**中継役**のタブは、制御役と実機の間に入ります。制御役は中継役につなぎ、中継役が実機につなぎ、通信は**そのまま**通しながら記録されます。記録から、仮想の機器の定義の**下書き**([機器の定義の書き方](device-definition_JP.md))を作り、仮想の機器として試せます。

> 下書きは出発点です。仮想の機器が実機と同じに振る舞うことを**保証するものではありません**。記録が示すのは、記録している間に起きたことだけです。

> 中継役は **UDP** のデータグラムも通せます([UDP を使う](udp_JP.md)を参照)。UDP の記録からは、まだ下書きを作れません。

## 何に使うか

- 実機と別のプログラムが、実際に何をやり取りしているかを、マニュアルを読む前に**見る**ため。
- あとで**実機なしで練習する**ため。下書きは、つなげる仮想の機器になります。

## 使い方

1. **中継役**のタブを開きます。
2. **転送先**に、実機のアドレスとポートを入れます。指定できるのは、同じネットワーク内(プライベートアドレス)かこの PC の機器だけです。それ以外は、理由つきで断られます。
3. **待ち受け範囲**と**ポート**(`0` は空きポートを自動で選びます)を選んで**開始**を押します。制御役を、実機の代わりにどのアドレス・ポートへつなげばよいかが表示されます。
4. 制御役をいつもどおりに使います。両方向の通信が**通信ログ**に出て、**記録**のパネルに件数が出ます。
5. **この記録から下書きを作る**を押します。下書きのコマンド、確かさ、**確認すること**が表示されます。
6. **仮想の機器で試す**で、下書きを仮想の機器のタブに読み込みます(動作中の仮想の機器は先に停止してください)。**定義として保存…**で、編集できる JSON ファイルとして書き出せます。

記録は、自分で選んだ場所へ**保存…**でき、あとで**読み込み…**もできます(別の日に下書きを作る、など)。

## 中継役が約束すること、約束しないこと

- **約束:** 各方向のバイトは、同じ順序で、変更なしで届きます。片側の終了は反対側へ伝わり、制御役が送り終えたあとでも、返答は届きます。
- **約束しない:** TCP がデータをどこで分割・結合するか、正確なタイミング。記録が示すのは中継役が見たもので、両端が見たものとは違うことがあります。中継役は実機に自分の接続を張るので、TCP keepalive などの設定は引き継がれません。
- PC を守る上限: 同時に 8 接続、1 秒あたり新規 10 接続、記録 8 MiB、200,000 件。記録がいっぱいになると、**記録は止まりますが転送は続き**、その旨が表示されます。相手が 10 秒間読まない接続は切ります。実機が閉じたのに制御役が閉じない接続は、60 秒後に閉じます。

## 安全のために

- **自分のネットワークだけ。** 転送先は、プライベートアドレスかこの PC でなければなりません。アドレスは一度だけ調べて固定するので、あとから名前の指す先を変えられても影響しません。中継役が自分自身へつなぐことはありません。
- **ネットワーク全体で待ち受ける**(`0.0.0.0`)と、同じネットワークの他の機器が、中継役を通して、認証なしで転送先の機器へ命令を送れます。確認が出て、転送先のアドレスが示され、警告が表示され続けます。信頼できるネットワークでだけ使ってください。
- **記録には、パスワードや設定値が、送られたままの形で含まれることがあります。** 保存先は自分で選びます。アプリが勝手に保存したり、送信したりはしません。保存した記録には、ホスト名・アドレス・時刻は含まれませんが、内容から多くが分かることがあります。共有する前に確認してください。
- 上のことは、画面ではなくプログラムの本体(メインプロセス)が確認します。画面には、ファイルのパスも、記録や定義そのものも渡されません。

## 下書きの作り方

下書きに入るのは、記録から**確実に分かること**だけです。

1. コマンドの**終端文字**(CR・LF・CR+LF)を、数えて推測します。自分で選ぶこともできます。
2. 通信をメッセージに分け、各コマンドを、そのあとに来た返答と組にします。ただし、**コマンドが1つずつ送られたとき**だけです。最小の間隔(既定 250 ミリ秒)より短く続けて送られたコマンドは、どの返答がどのコマンドのものか分からないので、入れません。
3. いつも同じ返答だったコマンドは、その返答(終端も含め、見たとおり)をもつ定義のコマンドになります。返答がなかったコマンドは、返答しない定義のコマンドになります。どの接続も最初に同じメッセージがあれば、それが接続時のメッセージになります。

返答の終端は CR・LF・CR+LF のどれでもよく、コマンドごとに違っていてもかまいません。下書きは、実際のバイトをそのまま書きます。

### 確認すること

下書きが決められなかったことは、件数と例つきで一覧になります。

| 項目 | 意味 |
|---|---|
| 状態によって返答が変わるコマンド | 同じコマンドの返答が、時によって違った(例: 電源を入れる前と後の問い合わせ)。入れていません。変数を自分で書き足してください。 |
| 1回しか観測していないコマンド | 入れてありますが、1回の観測では、返答がいつも同じとは言えません。 |
| コマンドが続けて送られ、どの返答がどのコマンドのものか分からないもの | コマンドが続けて送られたか、間隔が最小より短かった。入れていません。 |
| 返答が複数の行に分かれているコマンド | 複数行の返答なのか、機器が自分から言ったことなのかは、記録だけでは区別できません。 |
| 終端のない返答 | 終端のない返答は、「返答なし」とは扱いません。そのコマンドは入れていません。 |
| 文字として読めないデータ、または長すぎる・多すぎる内容 | 入れていません。 |
| 接続したときのメッセージが接続ごとに違う | 接続時のメッセージは入れていません。 |
| 機器の状態(変数)は、記録から推定しません | 機器の状態は、記録から**決して**推測しません。 |

### どのくらい確かか

記録に接続が2回以上あるときは、一部の接続から下書きを作り、残りの接続で試して、同じ返答になったコマンドの数を示します。目安にすぎません。状態によって変わるコマンドは不一致として数えますし、一度も見ていないコマンドを実機がどう扱うかは、アプリには分かりません。

## まだできないこと

UDP の記録からの定義の下書き、ログインやチャレンジ・レスポンスの握手、通信の改変や注入、複数の転送先、記録からの変数や状態の推測、終端のないメッセージ(固定長・長さ前置)。
