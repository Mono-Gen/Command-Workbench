# 仮想の機器の定義の書き方

[English](device-definition.md)

「仮想の機器」のタブは、*定義ファイル*のとおりに振る舞う、仮想の機器を動かします。このページは、その定義の書き方の説明です。定義は小さな JSON ファイルで、変数(機器の状態)、コマンド(何を理解して、何を返すか)、通知(機器が自分から言うこと)、接続の挙動(上限、無通信での切断、起動直後の無応答)を書きます。

これは**プログラミング言語ではありません**。式・スクリプト・正規表現はありません。そのため、定義は読みやすく、安全に読み込めます。

> 仮想の機器は、定義に書かれたとおりにしか動きません。練習のため、そして、よくある機器の挙動に制御側がどう対応するかを見るための道具です。**実機の動作の保証ではありません**。

## かんたんな方法: 表から定義を作る

最初の定義は、JSON を書かなくても作れます。**仮想の機器**のタブで**表から定義を作る…**を押すと、機器のマニュアルにあるコマンドの表のような、入力の画面が開きます。

- **コマンド**: 機器が受け取る内容です。終端文字は書きません(例: `PWR?`)。
- **返答**: 機器が返す内容です(例: `PWR on`)。**黙って受け付ける**コマンドは、空のままにします。

表の上では、**名前**、**TCP か UDP**、**終端文字**(CR・LF・CR+LF)、TCP のときは**接続時のメッセージ**(省略できます)を選びます。**知らないコマンドへの返答**も決められます。

- 選んだ終端文字は、すべての返答、接続時のメッセージ、知らないコマンドへの返答の末尾に自動で付きます。セルには書かないでください。セルの末尾に `[CR]` のような終端文字があると、誤りとして示されます。
- 返答の中では、`[TAB]` や `[LF]` などの表記を、制御役と同じように使えます。
- 入力した内容は、すべてそのままの文字として扱われます。`{`・`}`・`*` に特別な意味はありません(JSON の定義では意味があります)。
- コマンドの前後の空白は無視されます。同じコマンドの行が2つあるのは誤りです。先の行がいつも使われるためです。
- **マニュアルの表を貼り付けて追加する**では、表計算ソフトやマニュアルからコピーした行を貼り付けられます。1行が1コマンドで、コマンドと返答はタブで区切ります。セルの末尾にある終端文字は、取り除かれます。
- 表の下の**制御役のコマンド集にも追加**は、表のコマンドを、制御役の機器の保存コマンドとしても登録します。マニュアルの表を、1回写すだけで済みます。登録先は、保存済みの機器か、新しい機器(名前・宛先・ポート。仮想デバイスが動いている間は、そのポートが自動で入ります)から選びます。制御役のタブから送ると、仮想デバイスが、表のとおりに答えます。セルの文字は、入力したとおりに送られます(コマンドの前後の空白だけは取り除かれます)。登録先にすでに同じ名前のコマンドがあるときは、上書きせずに飛ばし、追加した件数と飛ばした件数を示します。
- 右の**できあがる定義(JSON)**は、表を直すたびに変わります。**この定義を使う**が読み込むもの、**名前を付けて保存…**が書き出すものと、まったく同じです。書き方の見本にもなります。**名前を付けて保存…**は、プログラムと同じ場所の `samples` フォルダ(あれば)を最初に示すので、保存したファイルは、**一覧を更新**すると、**定義**の一覧に出ます。

**定義を読み込む…**では、既存の JSON 定義に、表で表せる内容だけがあるとき、その内容を表へ入れられます。対象は、名前、TCP または UDP、3種類の終端文字、接続時のメッセージ(省略可)、固定文字列のコマンドと1つの固定返答(または無応答)、知らないコマンドへの固定返答(省略可)です。状態、変数、条件、遅延、通知、複数の返答、独自の区切り方など、表で保持できない内容が1つでもある定義は、理由を示して全体を拒否します。一部だけを読み込んで残りを黙って捨てることはありません。

表で作れるのは、決まった返答だけです。状態をもつ機器(`PWR 1` のあとで `PWR?` への答えが変わる)、条件、通知、接続の癖が必要なときは、このページの残りで説明する JSON を書いてください。ここで保存したファイルを、テキストエディタで直して始められます。

## サンプルと自作の定義

プログラムと同じ場所の `samples` フォルダに、付属の定義が普通のファイルとして入っています。開けば、定義の書き方が分かります。複製して書き換え、同じフォルダに保存すると(ファイル名は英数字と `.` `_` `-` で、`.json` で終わり、64 文字まで、1 MiB 未満)、機器役のタブで**一覧を更新**したあとに**定義**の一覧に出ます。使えないファイル(JSON として壊れている、`name` がない)は、理由つきで一覧に出て、選べません。JSON としては正しくても、以下の規則に反するファイルは、読み込んだときに、すべての問題が位置つきで示されます。`samples` フォルダがなければ内蔵のサンプルを使い、フォルダがあれば、空でもそのフォルダだけを使います。**ファイルを選ぶ…**で、どこにある定義ファイルでも読み込めます。

## 最初の定義

```json
{
  "schemaVersion": 1,
  "name": "My first device",
  "framing": { "terminator": "cr" },
  "greeting": "HELLO[CR]",
  "variables": {
    "power": { "type": "enum", "values": ["standby", "on"], "initial": "standby" }
  },
  "commands": [
    { "pattern": "PWR ?", "reply": "PWR {var.power}[CR]" },
    {
      "pattern": "PWR {state}",
      "capture": { "state": { "map": { "0": "standby", "1": "on" } } },
      "do": { "set": { "power": "{capture.state}" } },
      "reply": null,
      "invalid": { "reply": "ERR 1[CR]" }
    }
  ],
  "notifications": [
    { "when": { "var": "power", "changes": true }, "send": "EVT PWR {var.power}[CR]" }
  ],
  "unknown": { "reply": "ERR 2[CR]" }
}
```

「仮想の機器」のタブで**ファイルを選ぶ…**(または、同梱のサンプル2つのどちらかを読み込むと、より多くの機能が見られます)を押し、**開始**して、制御役のタブから接続します。`PWR ?[CR]`、`PWR 1[CR]`、`PWR 7[CR]`、`HELLO?[CR]` を試して、両側のログを見てください。

起きること: `PWR ?` は状態を返します。`PWR 1` は状態を変えて、**何も返しません**(成功したときは無言の機器が多くあります)が、通知は送られます。`PWR 7` は `map` にないので、`invalid` の返答 `ERR 1` が返り、何も変わりません。未知のコマンドには `ERR 2` が返ります。

## トップレベルの項目

| 項目 | 意味 |
|---|---|
| `schemaVersion` | 常に `1`。 |
| `transport` | 省略できます。`"tcp"`(既定)か `"udp"`。UDP は[UDP を使う](udp_JP.md)を参照してください。データグラムが1メッセージで、接続の代わりに送信元を管理し、`greeting` は書けません。 |
 アプリに表示されます(名前は1〜100文字、説明は500文字まで)。 |
| `framing.terminator` | `cr`・`lf`・`crlf` のどれか。**メッセージ**は、終端の前までのバイトです。`crlf` では、CR LF の組だけが終端です。4096 バイトを超えるメッセージは捨てられ、未知として扱われます。 |
| `greeting` | 接続を受け付けた直後に送る文で、接続時のメッセージです(省略できます)。`"transport": "udp"` では書けません(送る相手になる接続がないため)。 |
| `connection` | 上限とタイミング(下記)。 |
| `variables` | 機器の状態。 |
| `commands` | 機器が理解するもの(順番に意味があります)。 |
| `notifications` | 変数が変わったときに機器が送るメッセージ。 |
| `unknown` | どのコマンドにも合わなかったときの返答(`{ "reply": ... }`)。省略すると無言です。 |

知らない項目はエラーになります。綴り間違いが黙って無視されることはありません。

## 変数

名前は、小文字・数字・`_` で、英字から始めます(32文字まで)。すべての変数に `initial`(初期値)が必要です。

| `type` | 追加の項目 | 備考 |
|---|---|---|
| `enum` | `values`: 重複のない空でない文字列を 1〜64 個 | 値は、その中のどれかです。 |
| `int` | `min`, `max`(省略できます) | 整数。 |
| `bool` | なし | `true` / `false`。 |
| `string` | `maxLength`(64 まで) | 文字列。 |

## コマンド

各コマンドには `pattern` があり、必要に応じて `capture`、`when`、`do`、`reply`、`delayMs`、`otherwise`、`invalid`、`caseInsensitive` を書きます。

### パターン

パターンは、メッセージ**全体**(UTF-8 のテキスト)と照合されます。

- ふつうの文字は、完全に一致する必要があります(`PWR ?`)。空白も文字として数えます。
- `{name}` は、**空白を含まない1文字以上**を取り込みます。取り込みは、次の文字列が始まる**最も早い**位置で終わります。
- `*` は任意の文字列(空白を含んでよい)に合い、取り込みはしません。1つのパターンに1個までです。
- 文字としての `{`・`}`・`*` は、`{{`・`}}`・`**` と書きます。
- 取り込みどうし(や、取り込みと `*`)の間は、文字で区切る必要があります。取り込みは1つのパターンに4個までです。
- `"caseInsensitive": true` は、*文字そのもの*の A-Z の大文字小文字だけを無視します。取り込んだ文字列の大文字小文字は、そのままです。

**パターンが合った最初のコマンドが使われ、後ろのコマンドは試されません。** そのため、より具体的なパターンを先に書きます。

```json
{ "pattern": "PWR ?",         "reply": "PWR {var.power}[CR]" },
{ "pattern": "PWR {state}", "...": "..." }
```

`PWR {state}` を先に書くと、`PWR ?` の `?` を取り込んでしまい、その検査で失敗します。これが最もよくある間違いです。

### 取り込みと `map`

`"capture": { "state": { "map": { "0": "standby", "1": "on" } } }` は、取り込んだ文字列を、別の値に読み替えます(マニュアルによくある、数値の意味表です)。取り込んだ文字列が、キーのどれかと完全に一致しないと、そのコマンドは `invalid` の経路に進みます。

### `when`・`do` と3つの結果

- `when` は、すべて成り立つ必要のある条件の一覧です: `{ "var": "power", "is": "on" }`、`isNot`、`in: [...]`、整数なら `min` / `max`。値は、ふつうの JSON の値で書きます(`{capture...}` の参照は書けません)。
- `do.set` は、変数を変えます: `{ "set": { "input": "{capture.n}" } }`、または `{ "set": { "power": "on" } }` のような固定値。取り込みから値を取るときは、**ちょうど** `"{capture.NAME}"` と書きます。
- 取り込んだ値は、変数の型に変換されます。`int` は `0`・`5`・`-3` を受け付けますが、`007`・`+1`・`1e3` は**受け付けません**。`min`〜`max` の範囲内でもある必要があります。`enum` は、`values` のどれかと一致する必要があります。どれかが合わないときは、**何も変わらず**(すべての `set` は、まとめて適用されるか、まったく適用されないかです)、`invalid` が実行されます。
- 返答の種類: `reply`(成功)、`otherwise`(`when` の条件が成り立たなかった)、`invalid`(値が合わなかった)。`otherwise` / `invalid` を書かなければ、`unknown` の返答が使われます。`"reply": null`(または `reply` を省略)は**無言**です。成功を知らせない機器の挙動です。

### 返答

返答は、文字列、または、連結される文字列の配列(複数行に便利)です。次を使えます。

- `{var.NAME}` — 変数の現在値(このコマンドによる変更の後)。
- `{capture.NAME}` — 取り込んだ値。
- `[CR]`・`[LF]`・`0x0D`・`\r` などの書き方 — **固定の文字だけ**に書けます。値に `[CR]` という文字が含まれていても、CR ではなく、文字として送られます。
- `{{` と `}}` — 文字としての波括弧。

`delayMs`(0〜60000)は、機器の返答を遅くします。遅れた返答は、後ろの返答を待たせます(機器は1つずつ処理します)。

## 通知

```json
"notifications": [
  { "when": { "var": "power", "changes": true }, "send": "EVT PWR {var.power}[CR]", "to": "all" }
]
```

変数の値が**実際に変わったとき**に送られます(同じ値をもう一度設定しても、送られません)。`to` は `all`(接続中のすべての制御役。送信元を含む。既定)または `sender` です。通知は、コマンドの返答の後に続きます。通知で使えるのは `{var.NAME}` だけです。

## 接続の挙動

すべて省略できます。`"transport": "udp"` のときは、同じ項目が接続ではなく**送信元**(アドレスとポート)を数えます。`maxConnections` は同時に扱う数(それ以外の送信元のデータグラムは、`overLimit` に関わらず無視)、`idleTimeoutMs` は無言の送信元を覚えておく時間(0 なら300秒)、`idleBehavior` は常に「送信元を忘れる」です。

| 項目 | 意味 |
|---|---|
| `maxConnections` | 同時に接続できる制御役の数(1〜32、既定 1)。 |
| `overLimit` | `refuse`: 余分な接続をすぐ閉じる。`accept_then_close`: 接続時のメッセージを送ってから閉じる(待ち受け中のポートは、1つの接続だけを本当に拒否できないので、どちらも、いったん受け付けます)。 |
| `idleTimeoutMs` | 制御役が、この時間(1000〜3600000。0 は無効)、**完全なコマンドを1つも送らない**と、`idleBehavior` が起きます。TCP keepalive は**数えません**。ネットワークが正常でも、静かな接続を切る機器がある、ということを体験するための設定です。 |
| `idleBehavior` | `close`: 接続を閉じる。`stop_responding`: 接続は残したまま、その接続では二度と返事をしない(状態は変わります)。 |
| `startupQuietMs` | **開始**の直後のこの間(0〜600000)の接続は、接続時のメッセージなしですぐ閉じられます。まだ起動中の機器のようにです。 |
| `minCommandIntervalMs` | 前のコマンドから、これより短い間隔で届いたコマンドは、無視されます。 |

## 上限

コマンド 500、通知 100、変数 64、パターンの長さ 256、メッセージ 4096 バイト、返答 4096 バイト、ファイル 1 MiB、入れ子の深さ 16。

## ファイルに誤りがあるとき

アプリは、すべての問題を、JSON Pointer の**位置**つきで一覧にします。たとえば `/commands/2/do/set/input` は、「インデックス 2 のコマンドの `set` の中の `input`」という意味です。ファイルを直して、もう一度選んでください。

## まだできないこと

UDP のブロードキャスト・マルチキャスト。ログインやチャレンジ・レスポンスの握手。正規表現。スクリプトや計算(たとえば「1を足す」)。コマンドなしに、機器が自分で起こす出来事(前面パネルのボタンなど)。終端のないメッセージ(固定長、先頭の長さ)。複数のポートを同時に待ち受けること。

## 動かしている間

- **待ち受け範囲**: `127.0.0.1`(この PC だけ。既定)または `0.0.0.0`(ネットワーク全体)。後者は、他の機器から接続できるので、確認と警告を出します。初回は、ファイアウォールが許可を求めることがあります。
- **ポート**: `0` は、空いているポートを選びます。指定するなら 1024〜65535 です。
- **異常の注入**: 次の N 件の返答を捨てる、すべての返答を遅らせる、応答を止める(ミュート)、全接続を今すぐ閉じる。機器が不具合を起こしたときの、制御側の挙動を見るための機能です。
