# UDP を使う

[English](udp.md)

3つのタブすべてで、TCP に加えて **UDP** を扱えます。制御役は機器へデータグラムを送り、仮想の機器はデータグラムに答え、中継役は両者の間でデータグラムを受け渡して記録します。このページでは、TCP との違い、各タブの使い方、UDP では分からないことを説明します。

> UDP には手ごたえがありません。何も返ってこないとき、データグラムが失われたのか、ポートが違うのか、ファイアウォールが捨てたのか、機器がそもそも答えないのか、プログラムには区別できません。ヒントは「考えられる原因」の一覧であり、結論ではありません。

## TCP との違い

| | TCP | UDP |
|---|---|---|
| 接続 | あります。拒否・切断・時間切れがあります。 | **ありません。**「接続」は送る準備をするだけで、機器がいるかどうかは分かりません。 |
| メッセージの区切り | バイトの流れで、終端文字で区切ります。 | **1データグラム=1メッセージ。** 1回に送ったものは、まとまって届くか、届かないかです。 |
| 届くこと | OS が確認して再送します。 | **保証なし。** 失われる、重複する、順序が入れ替わることがあります。再送も並べ替えもしません。 |
| 返答の出どころ | 同じ接続です。 | 機器によっては、**別のポートから**返したり、送信元ではなく**決まったポート**へ返したりします。 |
| 大きさ | 制限なし。 | 最大 **65507 バイト**。約 **1472 バイト**を超えると、ネットワークが分割したり捨てたりすることがあります。 |
| エラー | 拒否・リセット・時間切れ。 | Windows では、閉じているポートへ送っても**成功します**(エラーは報告されません)。 |

UDP の機器は、末尾の終端文字を省略可能として扱うことが多いです。仮想の機器は `ID?` も `ID?[CR]` も受け付けます。データグラムの末尾に終端文字があれば **1つだけ**外し、1つのデータグラムを複数の行に分けることはしません。

## 制御役のタブ

1. 機器のダイアログで通信方式に **UDP** を選び、アドレスとポートを入力します。使えるのは、自分のネットワーク内(プライベートアドレスか、このPC)だけです。ブロードキャストとマルチキャストのアドレス(自分のネットワークのブロードキャストアドレスを含む)は、1回の送信で多数の機器に届いてしまうので拒否します。
2. **接続** を押します。バッジには「UDP 送信の準備ができました(届くかは確認できません)」と出ます。意味はそれだけです。
3. コマンドを入力して **送信** を押します。1回の送信が1データグラムです。空のコマンドは送れません。

UDP だけの設定が2つあります。

- **ローカルポート。** 機器が返答をいつも決まったポートへ送るときに指定します。空欄か `0` なら空いているポートを自動で選びます。すでに使われているポートなら、その旨を表示します。
- **どこからの返答も受け取る。** 既定では、送信先からのデータグラムだけを受け取り、それ以外は OS が捨てるので見えません。機器が別のポートから返すときは、これを選ぶと、送信元つきで受け取れます。接続で絞れないので、そのポートに偶然届いた他のものも見えます。

UDP 専用のヒントは「返答がありません(UDP)」(ポート違い・別のポートへの返答・ファイアウォール・終端文字の不足など機器が受け付けない形式・TCP だけの機器)、「別の送信元から返答がありました」、「ローカルポートを使えません」、「データグラムが大きすぎます」です。拒否・切断に関する TCP のヒントは出ません。

他の機器を守る制限があります。新しい「接続」は10秒に5回まで、1ソケットあたり毎秒100データグラム・256 KiB までです。TCP の keepalive は UDP には適用されません。

## 仮想の機器のタブ

定義に `"transport": "udp"` を書くか(→[機器の定義の書き方](device-definition_JP.md))、一覧から定義 **Sample UDP unit** を選びます。このタブは接続の代わりにデータグラムを待ち受けます。

- 1データグラムが1つの要求です。返答は**送信元**へ、機器が待ち受けているポートから返します。
- 送信元(アドレスとポート)ごとに「**送信元**」として一覧に出ます。機器の状態は、TCP で複数の接続があるときと同じく、全送信元で**共有**されます。`all` 宛ての通知は、最近データグラムを送ってきた送信元へ届きます。
- `maxConnections` は同時に扱う送信元の数です。それを超える送信元のデータグラムは**無視**します(`overLimit` はどちらの値でも同じ)。`minCommandIntervalMs`・`startupQuietMs`・故障の注入は TCP と同じに働き、**全接続を閉じる** は「全送信元を忘れる」になります。
- 送信元は、`idleTimeoutMs` の間データグラムが来ないと忘れます。`0` のときは **300秒**です。`idleBehavior` はどちらも「送信元を忘れる」で、次のデータグラムでまた扱われます。
- UDP の定義には `greeting` を書けません。接続がないので、挨拶を送る場面がありません。
- 空のデータグラムは無視します。

**ネットワーク全体で待ち受けるとき。** UDP の送信元アドレスは**偽れる**ので、他の機器が仮想の機器に、第三者へ向けて返答を送らせることができます。確認ダイアログがこのことを伝え、プログラムは送る量(全体で毎秒約 32 KiB、送信元ごとに毎秒約 8 KiB)と受け取る量を制限します。これは影響を**減らす**ものであり、なくせません。ネットワーク全体での待ち受けは、信頼できるネットワークでだけ使ってください。

## 中継役のタブ

通信方式に **UDP** を選び、転送先(自分のネットワーク内の機器)を入力して開始します。制御役の接続先を、この中継役にします。

- 制御役からのデータグラムは、**そのまま・1つのまとまりで**機器へ渡します。機器からのデータグラムは、話している制御役へ戻します。
- 制御役(アドレスとポート)ごとに「**セッション**」を作り、それぞれが機器への専用の経路を持つので、返答は必ず正しい制御役へ戻ります。同時に8つまで、新規は毎秒10までです。
- セッションは、**制御役が最後に送ってから60秒**で終わります(機器からの通信では延びません)。どれだけ続けても1時間で終わります。次のデータグラムで、新しいセッションが始まります。
- 記録は**1データグラムが1項目**で、通信の種類(UDP)を持ちます。TCP の記録と同じく、アドレスも時刻も入りません。空のデータグラムは渡しますが、記録しません。記録は TCP か UDP のどちらか一方だけを持つので、切り替えるのは空のときだけです(必要なら先に保存するか消去します)。
- **UDP の記録からは、まだ下書きを作れません。** 記録の保存と読み込みはできます。
- ネットワーク全体で待ち受けるときは、仮想の機器と同じく返答を制限します(全体で毎秒約 32 KiB、セッションごとに毎秒約 8 KiB)。そのため、**8 KiB を超える返答はそこでは中継されず**、ログに出ます。送信元アドレスを偽れる、という注意も同じです。

## まだできないこと

ブロードキャスト・マルチキャスト(送信も受信も)、IPv6、データグラムの再送・並べ替え、行ごとの分割、握手やログイン、UDP の記録からの定義の下書き。

## トラブルシューティング

- **返答がない。** ポート・ケーブル・ファイアウォールを確認し、次に機器が期待する終端文字を確認します。説明書に「決まったポートへ返す」とあれば **ローカルポート** を指定し、別のポートから返すなら **どこからの返答も受け取る** を選びます。
- **「ローカルポートを使えません」。** 他のプログラムがそのポートを使っています。別のポートにするか、空欄にします。Windows では、ネットワーク全体に結びついたものと特定のアドレスに結びついたものが同じポートを同時に使えるため、衝突を検出できるのは同じアドレス同士のときだけです。
- **大きなコマンドに答えない。** 約 1472 バイトを超えると、ネットワークが捨てることがあります。コマンドは短くします。
- **初回にファイアウォールの確認が出る。** ネットワーク全体で待ち受けると、Windows が許可を求めることがあります。
